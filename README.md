## 特性

| 特性 | 说明 |
|:---|:---|
| **默认离线** | 普通模式全程不联网；仅当用户在 AI 助手里主动切到专业模式并点击评分时才请求网络 |
| **最小权限** | 只申请 `INTERNET`（专业模式需要）；不申请存储/相机/位置等，数据存应用私有目录 |
| **纯本地计算** | 估分算法是纯函数（`core:domain`），不联网、不调用任何大模型 |
| **毛玻璃 UI** | 基于 Haze 的 Glassmorphism 质感，支持浅色/深色 |
| **离线提示词** | 内置四六级主观题评分提示词，一键复制到剪贴板，粘到任意 AI 即可评分 |

## 快速开始

### 环境要求

| 项 | 版本 |
|:---|:---|
| JDK | **21**（系统默认的 JDK 26 过新，AGP 8.x 不支持） |
| Android SDK | compileSdk 36 |
| Gradle | 8.14.3（wrapper 自带） |

Android SDK 路径写在 `local.properties` 的 `sdk.dir`（该文件不提交到版本库）。

```bash
# 按你的实际路径设置
export JAVA_HOME="/path/to/jdk-21"
export ANDROID_HOME="$HOME/Library/Android/sdk"
```

### 构建与运行

```bash
./gradlew assembleDebug     # 构建 APK
./gradlew installDebug      # 安装到设备
./gradlew test              # 跑全部测试
```

产物位于 `app/build/outputs/apk/debug/app-debug.apk`（约 20 MB）。

## 核心功能

### 估分算法

#### 换算链路

```
客观题答对原始分（四六级听力 35、阅读 35）
        +  写作自评（0-15）
        +  翻译自评（0-15）
        ↓
   百分制总分（0-100）
        ↓  × 7.1
   710 分制总分（四舍五入取整，上限 710）
```

即：`总分 = (听力答对原始分 + 阅读答对原始分 + 写作自评 + 翻译自评) × 7.1`

听力与阅读的**原始总分恰好就是 35**，所以答对原始分直接等于百分制得分，无需额外系数。

#### 官方比例

| 部分 | 百分制 | 710 分制 |
|:---|---:|---:|
| 听力理解 | 35 | 248.5 |
| 阅读理解 | 35 | 248.5 |
| 写作 | 15 | 106.5 |
| 翻译 | 15 | 106.5 |
| **合计** | **100** | **710** |

及格线 **425 分**。

#### 题组配置

**听力（25 题 / 35 分）**

| 题组 | 题号 | 每题 | 小计 |
|:---|:---:|:---:|:---:|
| 听力 1-15 | 1-15 | 1 分 | 15 |
| 听力 16-25 | 16-25 | 2 分 | 20 |

四级全称：短篇新闻与长对话 / 听力篇章；六级：长对话与听力篇章 / 讲座讲话。

**阅读（25 题 / 35 分，四六级相同）**

| 题组 | 题号 | 每题 | 小计 |
|:---|:---:|:---:|:---:|
| 阅读 26-35 | 26-35 | 0.5 分 | 5 |
| 阅读 36-45 | 36-45 | 1 分 | 10 |
| 阅读 46-55 | 46-55 | 2 分 | 20 |

#### 写作/翻译档位

采用「档位 + 微调」两级输入：先点选档位卡片（默认取区间中位数），再用滑块在档位内微调。

| 档位 | 四级写作描述 |
|:---:|:---|
| 13-15 | 切题，表达思想清楚，文字通顺，连贯性好，基本无语言错误 |
| 10-12 | 切题，表达思想清楚，文字连贯，但有少量语言错误 |
| 7-9 | 基本切题，有些地方表达不够清楚，文字勉强连贯，语言错误较多 |
| 4-6 | 基本切题，表达思想不清楚，连贯性差，有较多严重语言错误 |
| 1-3 | 条理不清，思路紊乱，语言支离破碎 |
| 0 | 未作答或只有几个孤立的词 |

六级评分标准更严格，文案略有调整；翻译同理。

### 结果页

估分完成后展示总分、各模块得分与各部分占比。

![结果页：总分、模块得分与 6 部分占比环形图](docs/images/03-结果页.png)

*总分与模块得分（2×2 网格）、6 部分占比环形图、下方题组明细列表*

#### 各部分占比

结果页环形图展示 **6 个部分**的占比：

| 部分 | 说明 |
|:---|:---|
| 听力理解 | 两个题组（1-15、16-25）**合并为一项** |
| 阅读理解 · 选词填空 | 题组 26-35 |
| 阅读理解 · 长篇阅读匹配 | 题组 36-45 |
| 阅读理解 · 仔细阅读 | 题组 46-55 |
| 写作 | 自评 0-15 |
| 翻译 | 自评 0-15 |

> 题组明细列表仍是 5 组（听力 2 组 + 阅读 3 组），但**占比层面听力合并为一项**，
> 这样才与需求定义的 6 部分一一对应。

#### 难点：占比必须精确等于 100%

各部分独立四舍五入会导致总和 ≠ 100%。六等分时每项是 16.666…%，
各自四舍五入到 16.7% 就是 **100.2%**，环形图会出现明显缺口。

**解法：最大余数法 + 分配精度与展示精度对齐**

1. 以 **0.1%** 为最小单位（1000 个单位 = 100%）
2. 每项先向下取整
3. 剩余单位按「小数部分从大到小」逐个补给各项

这样各项之和**精确等于 100.0**，且无需最后再四舍五入。

```kotlin
// core/domain/.../ScoreCalculator.kt
val UNITS = 1000                       // 0.1% 为一个单位
val units = ratios.map { (it * UNITS).toInt() }.toMutableList()
var remainder = UNITS - units.sum()
// 余数补给小数部分最大的项
```

另外，**占比为 0 的部分不参与扇形绘制** —— `drawArc` 的起止角相同时会画出带描边的异常细线。

![历史记录页：筛选、备注折叠与操作菜单](docs/images/04-历史记录.png)

*筛选切换、总分卡片、备注单行折叠*

#### 趋势图

折线图用 Compose Canvas 手绘，带渐变填充与 425 及格虚线。

![趋势页：425 及格线与备注标记](docs/images/05-趋势图.png)

*折线趋势、425 及格虚线、圆环备注标记*

#### 长备注的处理策略

> 备注可能有几百字，直接渲染在折线图上会挤爆布局。

`LineChartWithNotes` 的五层隔离：

1. **坐标系内绝不渲染备注文字** —— 只画数据点
2. 有备注的点旁加一个 **6dp 的小圆环标记**，不占额外空间
3. **X 轴标签抽稀** —— 超过 6 个点时只显示部分，避免文字重叠
4. **点击数据点**才弹出 `RecordDetailBottomSheet`，完整备注在图表外部渲染、内部滚动
5. **图表高度固定**，备注再长也不改变图表尺寸

## AI 评分助手（单 App 双模式）

把一份完整的四六级主观题评分提示词内置到 App，
选择级别与题型后**一键复制**，粘贴到任意外部 AI 即可获得 15 分制评分。

**一个 App，两种模式，用户在助手内顶部切换。**

### 替换式导航（三屏）

> 不是层层叠加，而是**同层级替换**：进一层，上一层的按钮从屏幕上消失。

```
第一屏：  四级 | 六级
            ↓ 点四级
第二屏：  作文 | 翻译        ← 四级/六级按钮从这里消失
            ↓ 点作文
第三屏：  四级-作文 评分界面
```

实现方式是 `when (step)` **每次只渲染当前屏** —— 上一屏的按钮根本不在 Composition 里。
这是最可靠的「替换」语义，不依赖 zIndex 或显隐动画。状态机在 `core:domain/AssistantNavigation.kt`。

**第一屏** —— 只有四级 / 六级两个按钮：

![AI 助手第一屏：级别选择](docs/images/06-AI助手-级别选择.png)

**第二屏** —— 四级/六级按钮已消失，换成作文 / 翻译：

![AI 助手第二屏：题型选择](docs/images/07-AI助手-题型选择.png)

**第三屏** —— 评分界面：

![AI 助手第三屏：评分界面](docs/images/08-AI助手-评分界面.png)

**返回逻辑**

| 从 | 到 | 级别信息 |
|:---|:---|:---|
| 第三屏 | 第二屏 | **保留**（可改题型） |
| 第二屏 | 第一屏 | **清空** |
| 第一屏 | 关闭页面 | — |

**两个入口的起始屏不同**

| 入口 | 起始屏 | 原因 |
|:---|:---|:---|
| 首页「AI 评分助手」卡片 | 第一屏 | 让用户完整走一遍替换式导航 |
| 估分页「用 AI 精评」按钮 | 第三屏 | 已选定级别与题型，省去重复选择 |

### 提示词架构

```
common.md              角色设定 / 五档总原则 / 档内微调 / 降档红线 / 四六级差异
+ cet4-writing.md      120-180 词；四级容错基准；四级范文
+ cet4-translation.md  140-160 汉字；四级容错基准；四级扣分点
+ cet6-writing.md      150-200 词；六级严格基准；六级范文
+ cet6-translation.md  180-200 汉字；术语错译直接降档；扣 1-2 分
+ 【考试级别】【题型】【题目要求/翻译原文】【我的作答】
+ output-format.md     档位判定 / 维度分析 / 逐句诊断 / 升档关键 / 优化版本
```

拼接规则在 `core:domain/PromptAssembler.kt`（纯函数，可单测），
读文件在 `feature:aiassistant/PromptModuleLoader.kt`（IO + 缓存）。

四套模块的差异不只是数字，判分松紧也完全不同：

| | 四级 | 六级 |
|:---|:---|:---|
| 基础语法错误 | 累计 3-5 处通常只档内扣分 | **累计 3 处即可能降档** |
| 模板化语句 >30% | 扣分 | **得分限制在低档** |
| 翻译术语错译 | 档内扣分 | **直接判「重大语义偏差」，11 档 → 8 档** |
| 段落长度 | 140-160 汉字 | 180-200 汉字 |

原题目为空时插入「未填原题目，AI 可能无法判断切题度」提示；
超过 2000 字自动截断并提示核对题干。

### 双模式对比

| | 普通模式 | 专业模式 |
|:---|:---|:---|
| 界面 | 原题目 + 作答 + 生成提示词并复制 | 原题目 + 作答 + 开始 AI 评分 + 流式输出窗口 |
| 隐藏 | API Key、评分结果、思考过程区 | 复制按钮、提示词预览 |
| 联网 | **不联网** | 用户主动点击评分后才联网 |

#### 普通模式

填好原题目与作答 → 系统按上述规则拼好完整提示词 → 一键复制 → 粘贴到
DeepSeek / 豆包 / ChatGPT 等任意 AI。

**复制内容规则**

| 用户作答 | 复制结果 |
|:---|:---|
| 未填 | 只复制提示词（模板末尾保留「【我的作答】：」引导语） |
| 已填 | `提示词` + 空行 + `【我的作答】：` + 换行 + 作答内容 |

**反馈**：主按钮点击后变为「已复制 ✓」，1.5 秒后复原；
同时弹 Snackbar 提示「已复制，请打开任意 AI 粘贴」，并给触觉反馈。

#### 专业模式

需要先在设置里填 API Key、Base URL、模型名（支持任何 OpenAI 兼容接口，
默认 `https://api.deepseek.com/v1` + `deepseek-chat`）。

![API 设置弹窗：填写 API Key、Base URL 与模型名](docs/images/10-AI助手-API设置.png)

*专业模式的 API 设置弹窗，填写 API Key、Base URL 与模型名（图中信息已做脱敏处理）*


![AI 助手专业模式：输入区与流式输出窗口](docs/images/09-AI助手-专业模式.png)

*专业模式界面：上方原题目与作答输入区 +「开始 AI 评分」，下方 AI 评分过程流式输出窗口*

评分体验：

- 分阶段提示：「正在准备评分上下文…」→「AI 正在阅读你的作答…」
- AI 输出**逐字显示**，窗口可滚动并**自动吸底**
- 完成后**高亮档位判定与最终分数**

异常处理：

| 情况 | 处理 |
|:---|:---|
| API Key 缺失 | 提示去设置页填写，**不静默失败** |
| 流式中断 | **保留已输出内容**，提示是否重试 |
| 超时 | 上限 60s |
| 结果解析失败 | **原文照常展示**，不强行格式化 |

首次使用会弹窗明确告知「作答将发送至第三方 API」。

> **关于联网**
> 普通模式全程**不发起任何网络请求**。只有当用户**主动切到专业模式并点击评分**时才会联网。
> Android 权限是「允许」而非「强制」—— 不发请求就不会联网。
> 除 `INTERNET` 外无任何权限，不申请存储/相机/位置，数据存应用私有目录。

### 代码分层

| 层 | 职责 |
|:---|:---|
| `core:domain/ScoringPrompt.kt` | 占位符替换、文本拼接（**纯函数，可单元测试**） |
| `core:domain/PromptAssembler.kt` | common + 四模块拼接顺序（原题目处理） |
| `feature:aiassistant/PromptModuleLoader.kt` | 仅从 assets 读文件（IO + 缓存） |
| `feature:aiassistant/AiAssistantViewModel.kt` | 状态管理、替换式导航协调 |
| `feature:aiassistant/AiAssistantScreen.kt` | UI（只渲染当前屏） |
| `feature:aiassistant/pro/` | 专业模式：API 配置 + SSE 流式调用 |

刻意把「规则」放 domain、「IO」放 feature，这样拼接规则不用起模拟器就能测。

| minSdk / targetSdk | 26（Android 8.0）/ 34 |

### 为什么版本不是最新的

这些版本是**实测编译通过的组合**，不要单独升级其中一个：

- **Haze 锁 1.7.0** —— 1.7.3 的 AAR 元数据写死 `minCompileSdk=37`
- **compileSdk 36** —— AGP 8.13.2 的上限就是 36
- **Compose BOM 2026.05.01** —— 更新版本会引入 Compose UI 1.12.x（要求 SDK 37）
- **navigation 2.9.5 / lifecycle 2.9.4** —— 更高版本要求 SDK 37 或 AGP 9.1+

## 实现要点备忘

### 踩过的坑

- **`pointerInput` 的 key 绝不能含会随点击变化的量** —— 这是「点一下就疯狂自增」bug 的根因。
  按下改 `value` 会让 pointerInput 协程被取消重启，清理逻辑永不执行，
  留下一条孤儿协程每 100ms 加一次。修复方式是让连发逻辑由状态机在指针事件循环内驱动，
  **不 spawn 任何长生命周期协程**。见 `NumberStepper.kt` 注释
- **`PointerInputScope` / `AwaitPointerEventScope` 都不是 `CoroutineScope`** ——
  在 `awaitEachGesture` 内无法 `launch`，需改用状态机在事件循环内驱动
- **`core:data` 的 Room 与 `core:ui` 的 Haze 必须用 `api`** —— 因为 `CetScoreDatabase` 继承
  `RoomDatabase`、`GlassCard` 签名里出现 `HazeState`，用 `implementation` 会导致下游编译失败
- **`core:domain` 刻意用 `kotlin("jvm")`** 而非 android-library —— 估分是纯计算，
  测试跑得快且不受 minSdk 约束。该模块**不要声明 `jvmToolchain(17)`**
- **`ModalBottomSheet` 需要 `@OptIn(ExperimentalMaterial3Api::class)`** —— 历史页与趋势页都用了

### 架构约定

- **估分结果不塞进路由参数** —— 结果对象体积大，用导航级 `PendingResult` 暂存
- **`detailJson` 设了 `ignoreUnknownKeys = true`** —— 以后新增字段时老记录仍可解析
- **免责声明等全局文案收敛到 `core:ui/AppCopy.kt`** —— 避免多模块重复定义后漏改
- **网络代码集中在 `feature/aiassistant/pro/`** —— 只有专业模式用，普通模式完全不碰网络
- **两种 AI 模式做成单 App 而非构建变体** —— 模式是用户在运行时选的，
  拆包会导致用户装错版本、也割裂了设置项
- **Vico 依赖保留但当前零引用** —— 需求明确要求「用 Compose Canvas 手绘，不引入图表库」，
  环形图与折线图均为手绘实现；Vico 留在版本目录备用
