## CET_Score v1.6

四六级估分助手 —— 输入真实对错情况，算出 710 分制预估总分。

### 本次主题：让 AI 批改能留住

以前 AI 批改完就过去了，想回看只能重新评一次。这一版把批改接进了历史记录。

### 1. 批改旁边加了复制按钮

「AI 评分过程」标题右侧新增复制，点一下整段批改进剪贴板，按钮会短暂变成「已复制」。

- 评分进行中也能点，复制已经输出的部分
- 失败中断时同样可以复制已生成的内容
- 没有内容时按钮变灰

### 2. 批改可以保存了

评分完成后，输出窗口底部出现「保存这次批改」，点开有两个选择：

**保存到已有记录**
列出最近的估分记录（级别 · 时间 · 分数）。选中即保存。
如果那条记录已经存过同题型的批改，会先问一句「覆盖已有批改？」，
避免手滑把上次的报告冲掉。

**新建一条记录**
如果这场考试还没做估分，可以直接建一条只装批改的记录。
分数与题组明细都留空，历史页显示「仅 AI 批改」，
**不会显示成 0 分**，也不会被算进趋势图。

作文和翻译分开存，同一条记录可以同时挂两份批改，互不覆盖。

### 3. 保存下来的记录随时能改

历史页点开任意一条记录，新增「AI 批改」区域：

- **复制**：整段批改复制走
- **编辑**：直接在应用里改文字，改完保存立即生效（批改原文是 AI 写的，难免有需要手动修正的地方）
- **删除**：只删这一份批改，记录本身还在；删除前会确认

编辑框清空后保存，等同于删除该份批改。

批改块上方会显示用的是哪个 AI、什么时候改的，方便区分「DeepSeek 评的」和「我自己改过的」。

### 4. 数据库升级不会清空记录

这一版给记录表加了两个字段（批改 JSON、记录类型），数据库版本 1 → 2。

写的是显式迁移：只做两条 `ALTER TABLE ADD COLUMN`，不重建表，不删库。
升级后已有记录原样保留，新字段为空，等价于「这些记录还没有批改」。

发布前用真实 v1 库结构跑过迁移测试：

- 手工建一个 v1 库，塞两条旧记录（369 / 316）
- 用正式配置让 Room 执行 `MIGRATION_1_2`
- 结果：两条记录都在，所属类型正确，新列为空，迁移后还能正常写入批改

Room 的 schema 校验也通过了——如果迁移后的表结构与代码对不上，测试会直接失败，
不会等到用户手机上才崩。
